# 视觉参数选择器

仅在主 SKILL.md 的必要条件成立时读取。工具帮助用户比较视觉参数，不代替内容结构、布局和业务交互设计。

## 启动与文件保护

使用本技能的 assets/ui-studio.html。复制到当前项目目录前检查目标：不存在则复制；内容相同则复用；已有用户版本或不明来源文件则保留，改用 yibo-ui-studio.html 或新的明确文件名。路径用绝对路径并正确引用，不覆盖已有产物。

告诉用户打开生成的文件。需要浏览器工具时遵守当前工具的 URL 与权限策略；文件协议被阻止不能改走其他浏览器、CDP 或中转绕过。用户手动打开与 Agent 能否自动验证是两件事。

## 陪用户完成六步

1. 前期问：项目背景、核心动作、密度、深浅底、动效偏好与一句话定位。
2. 选预设：六套配色与基础参数，是相同内容上的风格起点，不是六个完整网站模板。
3. 调细节：颜色、形状、密度、字体和动效。
4. 组件：比较样式和反馈；示意控件不代表已实现业务功能。
5. 看效果：查看所选参数对应的样例。真实产品仍须用真实内容复核。
6. 拿结果：配置校验通过后下载/复制 ui-tokens.json 与 UI-DESIGN.md。

由用户决定，不代替用户全部选完。只解释卡住的步骤，不用冗长问卷阻塞已有明确方向的工作。用户已授权 Agent 决定的参数可以合理补全并说明。

工具使用系统字体，不加载外部资源。换电脑的字体观感可能不同；这不构成最终项目的字体限制。

## 接收结果并返回主流程

- 用户将下载文件放入项目，或明确告知选择结果。检查目标文件再写入，保留已有修改。
- 读取 JSON 的 color、space、radius、font、motion、components 与 meta.brief，核对 Markdown 一致性。
- 新产物注明 producer 和规则版本；旧 myui/tokens@1 产物仍可作为输入，不因历史标识而丢弃。缺少字段从上下文补齐，重要冲突再确认。
- 自行核算页面实际使用的颜色组合，不能只信任文件内 blockers 或 verified。配置有效不等于页面已验收。
- 参数选定后回到主流程第 1 步补齐内容结构和布局，再进入实现与检查。不要再次启动选择器。
- 对已有项目做增量 token 映射，保留原设计系统的变量和组件，明确必要差异。

## 规则与验证范围

设计取舍以 yibo-ui-design/SKILL.md 为准，细化检查见 design-checklist.md。导出说明引用规则来源和版本，不复制一套不可协商的审美黑名单。

HTML 阈值服务于实际计算的纯色组合，检查正文、次要文字、面板、按钮、强调色与必要边界。不能覆盖字体实际呈现、透明叠加、图片背景、键盘行为和所有视口，产物必须保留这个范围限制。

后续实现检查适用的正常、悬停、按下、焦点、禁用及业务状态。保留用户无动效选择，验证系统减弱动效后内容与反馈仍可辨识。

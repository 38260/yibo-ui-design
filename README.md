# zyb-ui-design

一个面向官网、落地页、作品集和展示型工具页的界面设计 Skill：先理解需求与已有设计系统，再设计、实现并验证；**内置视觉参数选择器，但只在满足必要条件时启用**。

原本这是两个独立 Skill（设计流程 + 独立的 UI 预设台）。实际使用中职责重叠、规则冲突、交接来回，因此合并为单一入口：预设台降级为内部工具，不再单独注册或触发。

## 目录结构

```text
zyb-ui-design/
├── SKILL.md                            唯一入口：范围、优先级、工作流程、阶段化依赖
├── references/
│   ├── manual-visual-selection.md      选择器：启动、文件保护、陪选、交接、验证范围
│   └── design-checklist.md             设计与验收清单：基线、可访问性、实现细节、汇报口径
└── assets/
    └── ui-studio.html                  零依赖单文件视觉参数选择器
```

## 触发方式

### 1. 设计任务（默认路径）

直接描述任务即可，Agent 会自行完成设计与实现，**不会先让你填问卷或选模板**：

- “用 zyb-ui-design 帮我设计一个产品官网。”
- “用 zyb-ui-design 改版这个页面，保留现有功能。”
- “用 zyb-ui-design 审查这个界面，先不要改代码。”

### 2. 视觉参数选择器（受限触发）

**默认不启动。** 只有满足以下一项时才打开：

1. 用户明确要求亲自选择或对照视觉参数。
2. 已检查需求、参考和品牌，仍有至少两个会显著改变整体效果的合理方向，且一次简短澄清后仍需直观比较。
3. 用户反馈表明文字沟通不足以表达偏好，需要实际对照参数。

明确不触发：普通“做页面/美化一下”、Agent 自己拿不定主意、用户说“你来定/要快”、局部改色或文案、已有明确参考稿或有效设计参数。

手选完成后回到设计计划，补齐内容结构与布局，再进入实现与检查，不会要求重复选择。

## 选择器做了什么

- 六套预设配色与基础参数，是**相同内容上的风格起点**，不是六个完整网站模板。
- 实时计算正文、次要文字、面板、按钮、强调色与控件边界的对比度；不合格配置禁用下载与复制。
- 导出 `ui-tokens.json`（面向实现）与 `UI-DESIGN.md`（面向人读），兼容早期 `myui/tokens@1` 产物。
- 单文件、系统字体、零外部请求；运行时不引入任何依赖。

## 设计原则

- **优先级**：用户明确要求与项目约束 → 已确认的项目设计系统/参数 → 本 Skill 的审美默认值。
- **三类规则分开**：质量要求（必须验证）、审美默认值（可被用户选择覆盖）、项目约束（仅在项目要求时生效）。
- **不把配置通过当页面验收**：选择器只校验列出的纯色参数组合，真实页面仍需检查状态、键盘、视口与减弱动效。
